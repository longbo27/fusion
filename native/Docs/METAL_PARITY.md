# Metal comparison with immutable Python V1.1

## Scope and reproducibility

Production.metal ports grayscale, noise/contrast estimation, structure tensor, Sobel/Tenengrad/Laplacian evidence, Gaussian aggregation, multiscale scores, top-three candidates, confidence, edge/depth cleanup, masks, protected ownership, Gaussian/Laplacian pyramids, sequential accumulation/reconstruction and final uint16 output. Standard/High/Maximum run without changing Python modules. Signed Laplacians and Float32 photographic fields are preserved.

Developer fixtures are generated by importing the unchanged golden modules. Native comparison exports scores, top candidates, confidence, cleaned labels, Float32 reconstruction and final RGB16. Fixtures/logs are outside Git:

```sh
.venv/bin/python native/Developer/generate_parity.py --artifacts /tmp/fs-parity
$BENCH --production-parity /tmp/fs-parity
```

24 combinations passed: flat, random texture, high-contrast edge, thin branches, two focus planes, odd dimensions, halo scene and similarity-affine scene × three qualities. Maximum fixture extent is 257×193. Affine inputs use the actual golden Source.warp_tile global inverse-remap path. The benchmark reads original RGB16 and supplied transforms, not already warped images.

## Numerical results

Score error is maximum absolute difference divided by max(1, maximum expected score), rather than per-pixel relative error around zero. Across scenes/qualities it was at most 2.253e-7. Confidence maximum absolute error was 1.222e-6. Standard final images were exact, including affine. High/Maximum affine scores/candidates/labels agreed within Float32 score tolerance, with zero candidate/label mismatches and final max one uint16 code.

Declared small-fixture gates are score ≤2e-6, confidence ≤1e-4, candidate agreement ≥99%, label agreement ≥99.5%, final maximum ≤128 codes. These are prototype regression limits, not a universal photographic error guarantee. Strict greater-than selection remains unchanged; ties are not biased artificially to force reference agreement.

Native small-tile versus large-region comparisons, with identity and nontrivial similarity transforms, pass a separate ≤2-code seam gate. Global dyadic phases, image-edge reflection and expanded halos are exercised.

## First divergence investigation

Earlier large differences came from implicit FMA contraction, Gaussian accumulation order and OpenCV remap/Sobel arithmetic. Safe math and selected explicit FMAs now reproduce those operations. For the first real 1120² expanded region, remapped RGB and grayscale were exact; local moments/mixed-statistics Gaussian results were exact in the inspected buffers. The earliest remaining inspected difference was Float32 residual/noise arithmetic at ulp scale. Final score maxima versus reference were 1.819e-7/1.229e-7/1.158e-7 relative to score peak, and cleaned labels were identical over 1,254,400 pixels in that region. Later nearly tied score comparisons can amplify a few ulps into a different ownership label. OpenCV's official filter/remap source informed arithmetic ordering, not algorithm changes.

## Real output sampling

The final 101.897952MP three-frame output used native transforms. Re-running Python fusion with exactly those transforms compared seven distributed core tiles, totaling 20,563,968 RGB channel values. Six cores had maximum one code; the final edge core had ten channel values above one code, maximum **365**. Every sampled core's 99th-percentile error was zero; mean errors ranged 0.000081–0.000590 codes. This is sampled validation, not full-image Python parity. Every TIFF output segment was independently checked against its native staging pixels for integrity.

```sh
.venv/bin/python native/Developer/compare_real_stack.py \
  --report "$NATIVE_REPORT" --output "$NATIVE_TIFF" "$SOURCE1" "$SOURCE2" "$SOURCE3"
```

The report may contain progress lines before its JSON. This developer workflow reads only required output strips/tiles, uses bounded golden tile fusion and leaves private imagery out of Git. Production replacement still needs broader photographic/registration testing and tighter handling of numerically unstable ownership cases.
